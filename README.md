| ------- | -------: | -------: | -------: | -------: | -------: | ------: |

В моем эксперименте Release оказался быстрее Debug примерно в 2 раза

Что я обнаружила при сравнении IL

В Debug присутствуют интрукции nop, которых нет в Release.

В Debug объявлена секция local init с двумя переменными. В Release этой секции нет и компилятор посчитал результат напрямую.

В Debug результат последовательно сохраняется и считывается из локальных переменных: stloc.0, idloc.0, stloc.1, idloc.1. В Release эти операции отсутствуют.

В Debug есть инструкция br.s IL_0009, которая передает управление на следующую инструкцию. 

В методе Add() количество инструкций изменилось с 10 (Debug) до 4 (Release).

В Debug размер кода метода - 11 байт, а в Release - 4 байта.

## Ответы на контрольные вопросы

1. Что такое IL и зачем он нужен между C# и машинным кодом?

IL — промежуточный код, который получается после компиляции C#-программы. Он нужен как промежуточный слой между исходным кодом C# и машинным кодом процессора.

2. Почему .dll можно декомпилировать?

Потому что внутри .dll находятся IL-инструкции и метаданные. Специальные программы, например ILSpy, могут восстановить код, похожий на исходный.

3. Какие отличия Debug и Release вы увидели в IL?

В Debug присутствуют дополнительные инструкции и промежуточные операции, которые частично удаляются или оптимизируются в Release.

4. Почему Release обычно быстрее Debug?

В Release компилятор применяет больше оптимизаций, поэтому программа обычно выполняется эффективнее.

5. Почему строковый пароль в .dll нельзя считать защищённым?

Потому что строковые данные могут находиться внутри сборки и быть обнаружены при анализе .dll. Поэтому пароль нельзя считать защищённым только потому, что программа скомпилирована.
